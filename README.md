# CryoSPARC — Open OnDemand Interactive App

An [Open OnDemand](https://openondemand.org/) batch-connect app that launches a
personal [CryoSPARC](https://cryosparc.com/) master + worker on a single compute
node of the Tufts `pax` cluster, running from a Singularity container. Users fill
out a form, the job is submitted to Slurm, and once CryoSPARC is up the session
card links straight to its web interface.

## Requirements

- Open OnDemand with the batch-connect `basic` template, configured for the `pax` cluster
- Slurm
- `singularity` available as an environment module
- CryoSPARC container images at
  `/cluster/tufts/apps/container/biocontainers/images/cryosparc_<version>.sif`
- Shared site partials (not in this repo):
  - `/etc/ood/config/apps/dashboard/batch_connect/partials/resource_discovery.erb` — builds the
    partition, cores, memory and GPU-type fields from live cluster data
  - `/etc/ood/config/apps/dashboard/batch_connect/partials/partition_qos.rb` — `PartitionQos.qos_for`,
    which decides the `--qos` for each partition
- A CryoSPARC license ID for each user

## Form fields

| Field | Description |
|---|---|
| Partition | Slurm partition (generated by `resource_discovery.erb`) |
| Number of Hours | Walltime: up to 48 h on public partitions, 168 h on contrib lab partitions |
| CPU cores / Memory | Limits adjust to the selected partition and GPU type |
| GPU type / Number of GPUs | Hidden on CPU-only partitions; `any` requests a GPU of any type |
| Software Version | CryoSPARC version (currently `5.0.1`) |
| Email (for CryoSPARC login) | Used to create the CryoSPARC admin user on first launch |
| CryoSPARC License | License ID, format `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx` |
| CryoSPARC working directory | Persistent location for the database, run directory and cache |
| SSD cache path | Particle cache location (default `/tmp`, which may be too small for large jobs) |
| Request priority start | Submits with `--qos=interactive` (capped at 4 h, 16 cores, 64 GB, 1 GPU); only shown on partitions where it applies |

## How it works

1. **Form** (`form.yml.erb`, `form.js`) — the resource-discovery partial supplies
   per-partition limits as `data-*` attributes; `form.js` uses them to rebuild the GPU
   options, clamp cores/memory/hours/GPUs, warn when every node with the chosen GPU is
   down or drained, and apply the interactive QOS caps.
2. **Submission** (`submit.yml.erb`) — builds the Slurm options. A GPU type such as
   `a100-40G` becomes `--gres=gpu:a100:N --constraint=a100-40G`; QOS comes from
   `partition_qos.rb`.
3. **Startup** (`template/before.sh.erb`, `template/script.sh.erb`) — picks a free port,
   writes the license to `~/.cryosparc/license_id`, copies the container's default `run/`
   directory into the working directory and sets the port, then:
   - **first launch**: creates the database and an admin user (login email, password =
     first 8 characters of the license ID), and writes an `initialized` marker;
   - **later launches**: clears stale lock files and sockets, starts the database, runs
     `cryosparcm database fixport`, and removes stale worker targets from previous nodes.

   Finally it connects the current node as a worker on the `default` lane.
4. **Readiness** (`template/after.sh.erb`) — waits up to 180 s for the port to open.
5. **Session card** (`view.html.erb`) — links to `http://<host>.pax.tufts.edu:<port>` and
   shows the login details.
6. **Cleanup** (`template/clean.sh.erb`) — stops CryoSPARC, removes stale worker targets,
   lock files, the `run/` directory and the per-job SSD cache.

## Working directory layout

```
<cryosparc_dir>/
├── cryosparc_database_<version>/   # MongoDB data (persistent)
├── cryosparc_cache/
├── run/                            # recreated each session
└── initialized                     # first-launch marker
```

The database directory is versioned, so switching CryoSPARC versions starts a fresh
database in the same working directory.

## Logging in

- **Email:** the address entered in the form
- **Password:** the first 8 characters of the CryoSPARC license ID

## Adding a CryoSPARC version

1. Place `cryosparc_<version>.sif` in the container images directory.
2. Add the version to the `version` options in `form.yml.erb`.

## Troubleshooting

- **Session never becomes ready** — check `output.log` in the session directory. CryoSPARC
  can take a while to start; refresh the page after a minute.
- **Lock file owned by another user** — a `/tmp/cryosparc-*.sock` left by someone else on
  the same node blocks startup; the log names the owner, who must remove it.
- **Job stays queued** — if the form warned that the chosen GPU type is unavailable, all
  matching nodes are down or drained. Pick another GPU type or partition.
